Adjectives & Adverbs of Manner

Reading & Vocabulary

1. Reading

What Makes Code Good?

Good code does its job correctly, but that is not enough. It must also be easy for other people to read. Programmers often spend more time reading code than writing it, so clear code saves a lot of time.

Messy code looks confusing, even when it works well. Clear and descriptive names help a lot. If a variable stores a price, the name price is better than a short name like p or x.

Comments are important too. A comment is a brief note in the code. The computer ignores it, but people read it. A useful comment explains why the code does something. A comment that only repeats the code is not useful. Some programmers write code fast and forget comments, so after a few weeks they can hardly understand it.

Programmers also test their code often. A small test can find a mistake quickly, before it becomes a big problem. Good programmers work carefully, but not too slowly. They keep things simple: they write a basic working version of the program, then improve it step by step.

  2. What does clear code save?
  3. What does the computer do with a comment?
  4. What should a useful comment explain?
  5. Why is the name price better than p or x?
  6. Why do programmers test their code often?

Grammar

Adjectives (прикметники)

Прикметник описує іменник і відповідає на питання який?

Де стоїть прикметник:

  1. Перед іменником: (a/an) + adjective + noun
    a clear name, a long function, useful comments
  2. Після дієслів be, look, sound, feel, seem:
    The code is short. · Your idea sounds good.
  3. Перед to + дієслово у конструкції easy / hard / difficult to …:
    The code is easy to read. · The error is hard to find.

Якщо прикметників кілька, думка (nice, useful) стоїть перед фактом (short, new): a nice short function.

Adverbs of manner (прислівники способу дії)

Прислівник описує дію і відповідає на питання як?

Як утворити прислівник:

Правило Приклад
adjective + -ly clear → clearly, careful → carefully, brief → briefly, bad → badly
-y → -ily easy → easily
-le → -ly simple → simply
Irregular good → well, fast → fast, hard → hard, late → late, early → early

Де стоїть прислівник:

  • Після дієслова: The function works correctly.
  • Після додатка (object): He writes the code carefully.
  • Не ставимо між дієсловом і додатком: ✗ He writes carefully the code.

Adjective or adverb?

Дієслово означає дію (work, write, run, explain) → прислівник.
Дієслово означає стан (be, look, sound, feel, seem) → прикметник.

good чи well?

  • good (adj): This program is good. This idea sounds good.
  • well (adv): The program works well. He codes well.

bad чи badly? (так само)

  • bad (adj): It is a bad program. The code looks bad.
  • badly (adv): The program works badly.

Існують пари слів, де додавання -ly повністю змінює значення:

Слово Значення Приклад
hard наполегливо (adv); важкий (adj) She works hard. Math is hard to learn.
hardly ледве, майже не I hardly understand this code.
late пізно (adv); пізній (adj) He sent the code late.
lately останнім часом I haven't written much code lately.
Lately, I haven't seen many bugs in my code.

Також: friendly, lovely, lonely закінчуються на -ly, але це прикметники: a friendly message.

too / very / enough

  • too = занадто, більше ніж потрібно (це проблема): The function is too long to understand.
  • very = просто дуже (проблеми немає): The program is very fast, and the users are happy.
  • enough = достатньо; стоїть після прикметника або прислівника: This comment isn't clear enough.
  • too + adj ↔ not + opposite adj + enough: The function is too long. = The function isn't short enough.

very, really, quite, a bit стоять перед прикметником або прислівником і показують міру: a bit < quite < very/really.

У деяких прикметниках ("сильних"/крайніх) слово very вже закладене всередині значення:

  • terrible / awful = very bad (жахливий)
  • wonderful / fantastic = very good (чудовий)

Тому ми не кажемо very terrible (бо це означало б very very bad). З такими словами вживаємо really: The error message was really terrible.

Speaking: The Code Review Puzzle

Puzzle

Ситуація: у проєкті є чотири файли: login.py, shop.py, game.py, timer.py. Кожен файл має:

  • код, який можна описати як: short, long, messy або clear;
  • програму, роботу якої можна описати як: quick, slow, good або bad.
