UX та цикли

Перевірка домашнього завдання: show_result()

Давай перевіримо, як ти реалізувала функцію show_result(words, score). Твій код у функції main() має виглядати приблизно так: 

def main():
    practice_words = get_practice_words()
    practice_words = limit_words(practice_words)
    mode = choose_mode()
    score = run_quiz(practice_words, mode)

    show_result(practice_words, score)

def show_result(words, score):
    print(f"\n📊 You've got {score}/{len(words)} correct!")

Що таке UX?

UX (User Experience) — це те, як людина відчуває себе під час використання програми. Чи зрозуміло їй, що робити? Чи ввічливо програма реагує на помилки? Чи не змушує починати все заново через дрібницю?

Код може ідеально працювати "за задумом" розробника і водночас мати жахливий UX. Давай подивимось на нашу програму. Запусти vocab_app.py і спробуй зробити кілька помилок.

Що зараз не так з нашою програмою (UX-чеклист):

  • Якщо ввести текст (наприклад, "two") замість кількості слів — програма падає з помилкою ValueError і закривається.
  • Якщо під час вибору режиму ввести 3 (або будь-яке інше число, крім 1) — програма працює так, ніби обрано режим 2, замість того, щоб перепитати (через те, що у нас написано просто else). А якщо ввести літери — взагалі падає з помилкою.
  • Якщо під час відповіді просто випадково натиснути Enter (нічого не ввівши) — це зараховується як неправильна відповідь, хоча користувач міг просто схибити по клавіатурі.

Сьогодні ми навчимося це виправляти двома різними способами!

Повторення: while + not in

Цикл while виконує своє тіло знову і знову, поки умова залишається True. На відміну від for, ми заздалегідь не знаємо, скільки разів він повториться. 

count = 0
while count < 3:
    print(count)
    count += 1

Коли варіантів відповіді скінченна кількість, можна перевірити, чи введене значення є серед дозволених — за допомогою in. У парі з while це дає цикл "питай, поки не введуть один із правильних варіантів": 

# приклад з in
color = input("Select a color: red, blue or green: ").strip().lower()
print(color in ("red", "blue", "green")) # поверне True або False

# приклад з while + not in
color = input("Select a color: red, blue or green: ").strip().lower()

while color not in ("red", "blue", "green"):
    color = input("Input red, blue or green: ").strip().lower()

Функції .strip() (прибирає зайві пробіли) та .lower() (зменшує регістр) тут дуже важливі, щоб програма не сварила користувача за випадковий пробіл або велику літеру.

Подібна ідея працює і для простішої перевірки — "питай, поки не введуть хоч що-небудь" (поки рядок пустий ""): 
name = input("What is your name? ").strip()

while name == "":
    name = input("Please, enter your name: ").strip()

Завдання 1: Захисти choose_mode()

Онови функцію choose_mode() так, щоб вона не приймала нічого, крім "1" або "2". Якщо користувач введе щось інше, програма має просити його повторити ввід.

Твій поточний код:

def choose_mode():
    print("\nHow would you like to practice?")
    print("1️⃣  English → Ukrainian")
    print("2️⃣  Ukrainian → English")

    mode = input("Choose mode (1 or 2): ").strip()

    return int(mode)

Запусти програму і перевір, що станеться, якщо ввести 3 або просто натиснути Enter.

Завдання 2: Захисти ask_question()

Та сама ідея, але інша перевірка: зроби так, щоб програма не приймала порожню відповідь (просто Enter), а перепитувала, поки користувач не введе хоч якийсь переклад.

Твій поточний код:

def ask_question(question, answer):
    print(f"\n📝 Translate: {question}")

    user_input = input("> ").lower().strip()

    if user_input == answer.lower().strip():
        print("✅ Correct!")
        return True

    print(f"❌ Correct answer: {answer}")
    return False

Нова тема: try / except

Як "ловити" помилки

Пам'ятаєш демонстрацію на початку уроку — коли програма "падала", якщо ввести не число? try / except — це спосіб "спіймати" таку помилку і дати програмі зреагувати на неї спокійно, замість того, щоб одразу завершитись.

Усе, що ми хочемо "спробувати", пишемо в блоці try, а те, що робити, якщо станеться помилка — у блоці except. Якщо все в try пройшло без помилок — except просто ігнорується.

Без try/except:

number = int("hello")
print(number * 2)
Traceback (most recent call last):
  ...
ValueError: invalid literal for int() with base 10: 'hello'

Програма одразу завершується на цьому рядку — решта коду взагалі не виконується.

З try/except:

number_input = input("Enter a decimal number: ")

try:
    number = float(number_input)
except ValueError:
    print("It is not a valid decimal number!")
    number = 0.0

print(number * 2)

Python спочатку намагається виконати код у try — перетворити number_input на float. Якщо це неможливо (ввели літери) — виникає ValueError, виконання одразу перескакує в except, друкується повідомлення, і змінна отримує запасне значення 0.0. Програма не "падає" — вона просто продовжує виконуватись із запасним значенням.

Типи помилок:

  • ValueError — коли тип даних правильний, але значення не підходить (наприклад, int("hello")).
  • TypeError — операція застосована до непідходящого типу (додавання числа і тексту).
  • ZeroDivisionError — ділення на нуль.
  • FileNotFoundError — файл, який намагаємось відкрити, не існує.

Важливо: except ловить лише той тип помилки, який ми вказали. Якщо вказати не той тип — програма все одно "впаде": 

try:
    number = int("hello")
except ZeroDivisionError:  # не той тип помилки!
    print("Цей рядок ніколи не виконається")

# програма все одно впаде з ValueError, бо ми ловили не ту помилку

Кілька except для одного try:

В одному блоці try може статись одна з кількох різних помилок — тоді для кожної пишемо свій окремий except: 

try:
    number = int(input("Enter a number: "))
    result = 10 / number
    print(result)
except ValueError:
    print("That's not a number!")
except ZeroDivisionError:
    print("Can't divide by zero!")

Python перевіряє підряд: якщо сталась ValueError — спрацює перший except; якщо ZeroDivisionError — другий. Спрацює лише один із них, а решта коду в try після рядка з помилкою — пропускається.

Завдання 3: safe_int()

Перш ніж змінювати основний проєкт, потренуймося. Створи зовсім нову, окрему функцію safe_int(text).

  • Функція має спробувати перетворити text на ціле число (int).
  • Якщо вдається — повертає це число.
  • Якщо не вдається — ловить ValueError, друкує повідомлення "It's not an integer!" і повертає None.

Завдання 4: ValueError у limit_words

Онови функцію limit_words() у своєму проєкті. Якщо ввід користувача не є числом, програма не повинна ламатися. Натомість вона має вивести повідомлення "That's not a number, I'll use the full list instead." і встановити ліміт рівним довжині всього списку слів.

Твій поточний код:

def limit_words(words):
    print(f"\n📚 There are {len(words)} words in the list.")
    limit = int(input("How many words would you like to practice? "))
    return words[:limit]

Завдання 5: Перевірка діапазону

Тепер додай у limit_words() ще одну перевірку за допомогою if.

Якщо введене ціле число, але воно занадто мале (менше або дорівнює 0) або завелике (більше за загальну кількість слів у списку), то виведи повідомлення "That's not a valid amount, I'll use the full list instead." і теж використай весь список.

Запусти програму і перевір, що станеться, якщо ввести 0, -5 та 100.

Бонус B: розшир safe_int()

Якщо потрібно ловити кілька типів помилок однаково, їх можна перелічити в дужках через кому, наприклад:
except (ErrorType1, ErrorType2):

Онови функцію safe_int(text) із Завдання 3 так, щоб вона так само спокійно повертала None, якщо їй передати відсутнє значення None замість тексту. Це викличе помилку TypeError, а не ValueError. Злови їх обидві в одному блоці!
